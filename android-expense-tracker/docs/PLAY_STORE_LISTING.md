## 7. Feature Graphic (1024 x 500 px)

**Required spec:** JPG or 24-bit PNG (no alpha), exactly 1024 x 500 px.

**Design direction:**
- **Layout:** Left third reserved for logo + wordmark ("Ledgerly") and tagline; right two-thirds shows a stylized phone mockup of the app's dashboard screen (expense list + a small donut chart) tilted at a slight angle for depth.
- **Background:** Solid or subtle gradient using brand primary color (deep teal/forest green, suggested hex `#0B6E4F` to `#0E8C63`) fading to a lighter mint (`#E8F5EE`) — conveys "money/growth" without looking like a bank.
- **Accent color:** Warm amber/gold (`#F2A93B`) used sparingly for a CTA-style highlight (e.g., a small "Tax-Ready" badge or checkmark icon) — evokes receipts/paper and contrasts well against the green.
- **Typography:** Clean, modern geometric sans-serif (e.g., similar to Inter, Poppins, or Manrope) — bold wordmark, lighter-weight tagline beneath it.
- **Copy on graphic:**
  - Headline: **"Ledgerly"**
  - Subhead: **"Business Expense Tracker for the Self-Employed"**
  - Optional small badge near the phone mockup: **"Schedule C Ready"**
- **Imagery motifs:** Receipt icon, simple line-art car (mileage), small bar/donut chart — keep iconography minimal and flat-style, avoid clutter since the graphic is shown small in search results and at the top of the store listing.
- **Safe zone:** Keep all critical text and logo elements within the center 80% of the canvas; Play Store UI can crop/overlay edges on some surfaces (e.g., TV, Wear OS carousels).

## 8. App Icon Guidance

**Required spec:** 512 x 512 px, 32-bit PNG with alpha channel, under 1MB.

**Design direction:**
- Simple, single recognizable symbol — recommend a stylized **ledger/notebook page with a folded corner**, or a **receipt silhouette with a checkmark**, rendered in brand teal/green (`#0E8C63`) on a white or soft mint background, OR an inverted version (white icon on solid teal background) for stronger contrast at small sizes.
- Avoid text in the icon (illegible at launcher sizes).
- Ensure the icon reads clearly at 48dp (smallest common launcher size) — test at actual mobile resolution, not just at 512px.
- Provide an **adaptive icon** (foreground layer + background layer) per Android adaptive icon spec so it renders correctly across circle, squircle, rounded-square, and square launcher masks.
- Maintain consistent visual language with the feature graphic and in-app branding (same green/amber palette).

### Screenshot Production Notes
- Use consistent device frame (e.g., a modern Pixel-style bezel-less frame) across all 8 images for visual cohesion; keep the same status bar styling (full battery, strong signal, clean time) on every shot.
- Keep caption overlays in the same font/brand color band (e.g., a solid teal bar at the top or bottom 15–18% of the image) so the set reads as a unified story when viewed as a strip on the store listing.
- Order matters: screenshots 1–3 should sell the core "ease of use" value prop since most users only view the first 2–3 before deciding; save mileage/settings for positions 7–8.
- Use realistic but clearly fictional sample data (no real names, addresses, or card numbers) in all screenshots.

## 11. Store Listing Best Practices Checklist

**Before submission:**
- [ ] App name, short description, and full description finalized and proofread (no placeholder text, no competitor trademarks)
- [ ] Feature graphic (1024x500) uploaded, on-brand, legible at thumbnail size
- [ ] App icon (512x512) uploaded, adaptive icon variants tested on multiple launcher shapes
- [ ] 8 phone screenshots uploaded in the recommended narrative order, captions consistent in style
- [ ] 7" and 10" tablet screenshots uploaded (if tablet support is enabled in the build)
- [ ] Optional: promo video (YouTube link, 30 sec–2 min) showing receipt capture → report export flow
- [ ] Privacy Policy URL live and publicly accessible (link to hosted version of `PRIVACY_POLICY.md`)
- [ ] Data Safety form completed and cross-checked against actual SDKs/permissions in the build (Firebase, Google Sign-In, Drive/Sheets API, Crashlytics)
- [ ] Content rating questionnaire completed
- [ ] Target audience & content settings configured (mark as not directed at children; set appropriate age range)
- [ ] App category set to **Finance**; tags set per Section 5
- [ ] Contact details (support email, optional website) completed in Play Console
- [ ] Tax/financial disclaimer included in full description ("not tax, accounting, or legal advice")
- [ ] All permissions requested in the manifest are justified and explained in the Privacy Policy (CAMERA, ACCESS_FINE_LOCATION, INTERNET, POST_NOTIFICATIONS, READ_MEDIA_IMAGES, USE_BIOMETRIC)
- [ ] OAuth consent screen (Google Cloud Console) configured with correct app name, logo, scopes (Drive/Sheets), and privacy policy link, and submitted for verification if using sensitive/restricted scopes
- [ ] Internal testing / closed testing track run before production release, including at least one full Schedule C export flow

**Post-launch / ongoing:**
- [ ] Monitor Play Console "Store listing experiments" for A/B testing icon, screenshots, and descriptions
- [ ] Update "What's New" notes with every release (avoid generic "bug fixes" only — briefly state what changed)
- [ ] Respond to user reviews, especially around tax-season traffic spikes (Jan–Apr in the U.S.)
- [ ] Revisit keyword strategy quarterly using Play Console search term performance data
- [ ] Re-review Data Safety form after any change to SDKs, permissions, or data flows (e.g., adding a new analytics tool)
- [ ] Localize listing copy for additional markets if expanding beyond English-speaking, U.S.-tax-focused users
